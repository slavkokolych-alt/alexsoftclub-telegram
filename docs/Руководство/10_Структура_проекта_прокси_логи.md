# 10. Прокси, папки и логи

Здесь - где что лежит в папке программы, как подключить прокси и где искать причину ошибки.

---

## Какие папки и файлы есть рядом с программой

| Папка / файл | Что там |
|--------------|---------|
| **`Аккаунты/`** | Папки-профили Telegram. Внутри каждого аккаунта программа создаёт подпапки `sessions/`, `stories/`, `avatars/`. |
| **`Аватарки/`** | Фото для аватарок: `Аватарки для аккаунтов/` (задача 1.7) и `Аватарки для личных каналов/` (задача 1.10). |
| **`Data/`** | Служебная папка: настройки программы и файлы для ИИ (`Data/AI/`). Настройки задаются через меню - вручную тут копаться не нужно. |
| **`База данных.db`** | Главный файл: все таблицы, ссылки, тексты и аккаунты. **Берегите его.** |
| **`log.log`** | Файл системных ошибок. |
| **`AlexSoftClub.exe`** | Запуск программы. |

---

## 🔒 Прокси - обязательно

<div class="box box-danger">
<b>⚠ Без прокси нельзя.</b> Запустить 100 аккаунтов с одного домашнего Wi-Fi (один IP) = мгновенный спам-блок сразу на все аккаунты. У каждого аккаунта Telegram должен "видеть" отдельного человека с отдельного устройства.
</div>

В программе **нет** общего файла прокси - вы вписываете прокси **индивидуально каждому аккаунту** в таблице `01 1 Менеджер аккаунтов`, в 4 отдельные колонки. Протокол - только **SOCKS5**.

| Колонка | Что вписать | Пример |
|---------|-------------|--------|
| `✅ IP прокси` | IP-адрес | `192.168.1.1` |
| `✅ Порт прокси` | Порт | `1080` |
| `✅ Логин прокси` | Логин (если есть) | `user123` |
| `✅ Пароль прокси` | Пароль (если есть) | `qwerty1234` |

После заполнения запустите **1 Менеджер аккаунтов → Проверка сессий** - программа зайдёт в Telegram через прокси. Если прокси плохой или "сгорел" - будет ошибка.

<div class="box box-tip">
💡 Рекомендация: <b>1 прокси на 1-2 аккаунта.</b> Больше аккаунтов на один прокси - выше риск, что Telegram свяжет их между собой.
</div>

## Настройки соединения

В главном меню есть кнопка **"Соединение"** - глобальные настройки подключения через прокси (действуют на все задачи).

| Параметр | По умолчанию | Когда менять |
|----------|--------------|--------------|
| **Таймаут подключения (сек)** | `10` | Ротационные/резидентные прокси подключаются не сразу - увеличьте до `15-30`. |
| **Попытки переподключения** | `5` | Нестабильные прокси - увеличьте до `7-10`. |
| **Переподключение через прокси (попытки)** | `3` | Резидентные прокси при переподключении выдают новый IP - больше попыток, больше шансов попасть на живой. |
| **Задержка переподключения через прокси (сек)** | `5` | Пауза между такими попытками. |
| **Общий таймаут подключения аккаунта (сек)** | `90` | Потолок на всё подключение одного аккаунта. Мёртвый прокси не задержит поток дольше этого времени. |
| **Попытки переподключения в мониторинге** | `3` | Сколько раз подряд задача мониторинга (Автоответчик, Комментинг, Лидхантер, Лайкер в чатах (М)) пробует переподключить аккаунт, прежде чем снять его с задачи. `0` - пробовать бесконечно. |

## Где искать причину ошибки (логи)

Программа пишет логи в двух местах:

1. **На экране** - цветные сообщения во время работы (зелёное "Успешно" и т.п.).
2. **В файле `log.log`** - системные ошибки. Если программа резко закрылась или задача не запускается, откройте этот файл Блокнотом и посмотрите **последнюю строчку** - там причина.

<div class="box box-tip">
💡 Частая причина ошибки записи - <code>База данных.db</code> открыта в SQLiteStudio с несохранёнными изменениями. Сохраните и закройте редактор перед запуском задачи.
</div>
