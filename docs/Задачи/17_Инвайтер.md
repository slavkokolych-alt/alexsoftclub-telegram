# 17. Инвайтер

> Раздел: **Инвайтинг и контент** · Тип: наполнение групп участниками

Инвайтер добавляет ваших пользователей в группы: аккаунты заходят в чат по ссылке и приглашают туда людей из списка (по юзернейму) или из своих контактов. Внутри задачи 5 режимов - обычный инвайт, назначение и снятие админских прав, инвайт "под админкой" для обхода лимитов и проверка чатов на ограничения.

---

## Смысл: зачем это нужно

Если у вас есть своя группа или чат клиента, её нужно наполнить живыми участниками. Инвайтер делает это автоматически: раздаёт список юзернеймов по аккаунтам и добавляет людей в указанные группы. Так вы быстро набираете аудиторию, не нанимая людей вручную.

<div class="box box-warn">
⚠ Telegram жёстко ограничивает инвайты. Реальная безопасная норма - примерно <b>40-50 приглашений в день на аккаунт</b>. Если гнать быстрее, аккаунт ловит блокировку инвайтов (спамблок) на сутки. Ставьте задержку <b>30-60 секунд</b> и не завышайте лимит на аккаунт.
</div>

---

## Как открыть задачу

1. В программе кликните **17 Инвайтер**.
2. Откроется подменю выбора режима - кликните нужный пункт:
   - **Инвайтер**
   - **Назначить админов**
   - **Удалить админские права**
   - **Инвайтер админами**
   - **Проверить чат на ограничения**
   - **Авто-инвайт админами**
   - **Инвайт новых подписчиков из чата-донора**
3. Выставьте настройки и нажмите **"Продолжить"**.
4. Введите задержку старта и нажмите **"Запустить"**.

## 17.1 Инвайтер

Базовый режим. Аккаунт заходит в группу и приглашает туда людей.

**Как работает по шагам:**

1. Аккаунт берёт группу из `17 2` и заходит в неё (подписывается, если ещё не состоит).
2. Берёт очередного пользователя - по юзернейму из `17 1` **или** из своих контактов (зависит от настройки "Брать пользователей").
3. Добавляет его в группу.
4. Делает паузу и берёт следующего, пока не наберёт свой лимит на аккаунт.

**Настройки:**

| Настройка | Что делает | Что ставить |
|-----------|-----------|-------------|
| **Кол-во юзернеймов на аккаунт** | Сколько человек пригласит один аккаунт за проход | `40-50` (не больше) |
| **Задержка после инвайта (сек)** | Пауза между приглашениями | `30-60` |
| **Брать пользователей (1 - из контактов 2 - из списка)** | Откуда берём людей: `1` - из контактной книги аккаунта, `2` - из таблицы `17 1` | `2` для работы по списку |
| **Режим инвайта (1 - По одному с паузой / 2 - Быстрый пачками)** | `1` - как описано выше, `2` - быстрый режим, см. 17.1.2 | `1` для бережной работы |

## 17.1.2 Быстрый режим (пачками) <span class="badge-new">Новое</span>

Режим для задач "залить чат за минуты, аккаунтов не жалко". Включается настройкой **Режим инвайта** = `2`.

**Чем отличается от обычного режима:**

1. Аккаунт сразу забирает из `17 1` всю свою пачку (столько, сколько стоит в "Кол-во юзернеймов на аккаунт").
2. Пробивает все юзернеймы подряд, без пауз.
3. Добавляет всю пачку в чат **одним запросом** - Telegram принимает до 100 человек за раз. Если в пачке больше 100, она уходит несколькими запросами, между ними выдерживается "Задержка после инвайта (сек)".
4. Пауза между людьми не делается вообще.

Так 10 аккаунтов с лимитом `100-100` заливают до 1000 человек за пару минут вместо нескольких часов.

**Что важно понимать:**

- Telegram даёт аккаунту пробить подряд примерно 50-100 юзернеймов, дальше ставит ограничение на часы. Поэтому лимит на аккаунт больше `100-100` ставить нет смысла: остаток пачки аккаунт всё равно не пробьёт, а сам уйдёт в ограничение.
- Аккаунт в этом режиме сгорает быстрее: ограничение резолва, флуд, спамблок - обычное дело после одного-двух проходов. Считайте аккаунты расходником.
- Лимит Telegram "сколько людей один аккаунт может добавить в один чат" (порядка 100-200) никуда не девается - берите количеством аккаунтов, а не лимитом на один.
- Людей с закрытой приватностью ("добавлять могут только контакты") Telegram молча не добавляет - они получают статус "Запрет на инвайт", как и в обычном режиме.
- Чат лучше делать приватным, а инвайтящим аккаунтам выдать админку с правом "Добавление участников" (задача 17.2): так добавление привлекает меньше внимания антиспама.

Если аккаунт остановился посреди пачки (флуд, ограничение), непройденные юзернеймы возвращаются в очередь и достаются следующему аккаунту - в `17 1` они снова без отметки.

**Рекомендуемые настройки для быстрого режима:**

| Настройка | Что ставить |
|-----------|-------------|
| Режим инвайта | `2` |
| Кол-во юзернеймов на аккаунт | `50-100` |
| Задержка после инвайта (сек) | `5-10` (действует только между пачками по 100) |
| Кол-во одновременно работающих потоков | по числу аккаунтов, например `10` |
| Задержка перед выполнением следующего потока (сек) | `2-5` |

## 17.1.3 Инвайт по ID (люди без юзернейма) <span class="badge-new">Новое</span>

В `17 1` можно вписать не только юзернейм, но и "✅ ID пользователя". Так приглашаются люди, у которых юзернейма нет: их даёт парсер с настройкой "Сохранять пользователей без юзернейма = 1".

Приглашение по ID Telegram принимает только от аккаунта, который сам видел этого человека в чате. Поэтому перед запуском нужна подготовка через парсер (раздел "Подготовка аккаунтов к инвайту по ID" в описании задачи 4): каждый аккаунт для инвайта один раз просматривает чат-источник и запоминает свои ключи доступа.

Как работает Инвайтер после подготовки:
- строка с ID уходит в инвайт без резолва и без задержек, в результатах `17 4` в колонке юзернейма стоит ID;
- строку с одним ID берёт только аккаунт, у которого есть ключ на этого человека. Остальные аккаунты её не трогают, лимит не тратится;
- строки с юзернеймом работают как раньше, подготовка им не нужна.

Если подготовку не делали, при старте у каждого аккаунта в консоли строка вида `строк только с ID в списке: 240, из них без хеша у этого аккаунта: 240 - такие строки аккаунт не берёт, запустите "4 Парсер пользователей" с настройкой "Парсить только людей из списка Инвайтера" = 1`. Юзернеймы при этом приглашаются как обычно.

Режимы 17.4 "Инвайтер админами" и 17.6 "Авто-инвайт админами" берут строки с ID так же: аккаунт с ключом добавляет человека через выдачу админки, подготовка через парсер нужна та же.

### Как Инвайтер решает, приглашать по юзернейму или по ID

Отдельной настройки нет, решение принимается по каждой строке `17 1`:

| В строке | У аккаунта есть ключ на этот ID | Как приглашает |
|----------|-------------------------------|----------------|
| ID (юзернейм вписан или нет) | Да | По ID, без резолва. Юзернейм не используется |
| Юзернейм, ID пустой или ключа нет | - | По юзернейму, как раньше: резолв, затем приглашение |
| Только ID | Нет | Строку не берёт, она достаётся аккаунту с ключом. Если ключа нет ни у кого, строка остаётся необработанной |

В результатах `17 4` видно, как приглашён человек: при инвайте по ID в колонке юзернейма стоит его ID.

### Чем инвайт по ID безопаснее

Инвайт по юзернейму делает два запроса на человека: резолв юзернейма (Telegram ищет, кто это) и само приглашение. Инвайт по ID делает один запрос: приглашение. Резолв незнакомых юзернеймов подряд - именно то действие, которое Telegram считает и ограничивает: у него свой суточный лимит около 200 на аккаунт, дальше ошибки и флудвейт на часы, а серия резолвов с инвайтом после каждого - один из сигналов для спамблока. Программа при серии отказов резолва останавливает аккаунт сама.

В цифрах: аккаунт приглашает 30 человек за круг. По юзернейму это 60 запросов, по ID - 30. При лимите резолвов аккаунт по юзернейму не сделает больше 200 инвайтов в сутки, даже если лимиты инвайта позволяют.

Парсинг и подготовка резолвов по людям не делают вообще: аккаунт один раз резолвит сам чат по ссылке, а дальше листает участников или сообщения страницами по 200, и Telegram отдаёт всех людей вместе с ID и ключами. 10 000 человек - это около 50 запросов. Поэтому один дешёвый проход канала даёт ключи на всех, а потом инвайт идёт без единого резолва.

Если объёмы небольшие, 20-30 человек на аккаунт в день, разница не принципиальна, и по юзернейму можно работать как раньше: обе новые настройки парсера на `2`, в `17 1` только колонка "Юзернейм".


## 17.2 Назначить админов

Служебный режим: аккаунт выдаёт админские права людям из таблицы `17 3` в указанных группах. Нужен, когда надо заранее раздать права нескольким людям в своих чатах.

**Настройки:**

| Настройка | Что делает | Что ставить |
|-----------|-----------|-------------|
| **Кол-во юзернеймов на аккаунт** | Сколько человек обработает один аккаунт за проход | `40-50` |
| **Задержка после назначения (сек)** | Пауза между действиями | `30-60` |

Кого назначать - берётся из таблицы `17 3 Инвайтер список админов для назначения`. Группы - из `17 2`.

## 17.3 Удалить админские права

Обратный режим к предыдущему: аккаунт снимает админские права у людей из таблицы `17 3` в указанных группах.

**Настройки:**

| Настройка | Что делает | Что ставить |
|-----------|-----------|-------------|
| **Кол-во юзернеймов на аккаунт** | Сколько человек обработает один аккаунт за проход | `40-50` |
| **Задержка после удаления прав (сек)** | Пауза между действиями | `30-60` |

Кого разжаловать - из таблицы `17 3`. Группы - из `17 2`.

## 17.4 Инвайтер админами <span class="badge-new">Обход лимитов</span>

Продвинутый режим приглашения. Работает так же, как обычный Инвайтер (17.1), но с трюком: аккаунт **на секунду повышает человека до администратора и сразу снимает права**. Отдельного приглашения тут нет - человека добавляет само назначение админом, а после снятия прав он остаётся обычным участником.

**Зачем это нужно:** Telegram разрешает администраторам приглашать в группу **в разы больше** людей, чем обычным участникам. Кратковременная выдача админки обходит стандартный лимит на инвайты - вы добавляете значительно больше людей с одного аккаунта.

**Что нужно аккаунту:** он сам должен быть администратором чата с включённой галочкой **"Добавление администраторов"**. Telegram выключает её по умолчанию, когда владелец выдаёт админку - её надо поставить вручную каждому рабочему аккаунту. Без неё Telegram отказывает, и в таблице `17 2` появится статус `Не хватает прав администратора`.

**Настройки:**

| Настройка | Что делает | Что ставить |
|-----------|-----------|-------------|
| **Кол-во юзернеймов на аккаунт** | Сколько человек пригласит один аккаунт за проход | `40-50` |
| **Задержка после инвайта (сек)** | Пауза между приглашениями | `30-60` |
| **Брать пользователей (1 - из контактов 2 - из списка)** | Откуда берём людей: `1` - из контактов, `2` - из таблицы `17 1` | `2` для работы по списку |
| **Выходить из чата после пачки (1 - Да / 2 - Нет)** | `1` - аккаунт после своей пачки выходит из чата (ротация, см. ниже), `2` - остаётся в чате как раньше | `2` для обычной работы |

<div class="box box-tip">
💡 Ставьте диапазоны с разбросом ("30-60", а не "45-45") - ровный ритм выдаёт автоматизацию. Даже с обходом лимитов не завышайте "Кол-во юзернеймов на аккаунт" - аккаунт всё равно можно спалить массовыми действиями.
</div>

### Ротация: выход из чата после пачки

Режим для быстрой заливки крупного чата пулом аккаунтов. Включается настройкой **Выходить из чата после пачки** = `1`.

Как работает один заход аккаунта:

1. Аккаунт заходит в чат по ссылке-приглашению.
2. Втягивает свою пачку людей (сколько стоит в "Кол-во юзернеймов на аккаунт").
3. **Выходит из чата.**

Чтобы аккаунт сделал следующую пачку, задачу запускают заново (вручную) либо ставят "Кол-во циклов" больше 1 - на новом заходе аккаунт снова войдёт по ссылке и возьмёт следующую пачку. Так один аккаунт делает несколько коротких визитов вместо одного долгого - за один визит он меньше "светится".

**Схема заливки большого чата пулом аккаунтов:**

- держите пул аккаунтов (например 30), все с доступом к чату по ссылке;
- заранее раздайте рабочим права через задачу **17.2 Назначить админов** (нужно право "Добавление администраторов");
- в 17.4 поставьте небольшой лимит на заход (`20-30`), короткую задержку (`5-15`), потоков - по числу аккаунтов;
- запускайте задачу **волнами**: одна волна = один запуск на своей группе аккаунтов. Между волнами давайте аккаунтам отдохнуть.

<div class="box box-warning">
⚠️ Это агрессивный режим. Аккаунты в нём расходуются быстро: массовая раздача прав и вход-выход - заметная активность. Разным волнам лучше давать разные аккаунты, а не гонять одни и те же подряд.
</div>

## 17.6 Авто-инвайт админами <span class="badge-new">Новое</span>

Конвейер в один запуск: главный аккаунт сам раздаёт права рабочим, рабочие приглашают людей из списка, в конце права снимаются. Повторяет схему массовой заливки чата пулом аккаунтов, но без ручного запуска трёх отдельных задач.

**Как работает за один запуск:**

1. **Фаза 1.** Главный аккаунт выдаёт каждому рабочему полный набор прав в чате.
2. **Фаза 2.** Каждый рабочий заходит по ссылке, приглашает свою пачку людей (правами "Добавление пользователей" + "Анонимность", затем снимает их - человек остаётся в чате), после пачки выходит из чата.
3. **Фаза 3.** Главный аккаунт снимает с рабочих все выданные права.

**Что подготовить:**

- Все аккаунты (главный и рабочие) добавлены в Менеджере аккаунтов и свободны.
- Главный аккаунт уже состоит в чате и имеет полные права, включая "Добавление администраторов".
- Таблица **17 2** - ссылка-приглашение на ваш чат.
- Таблица **17 1** - @username людей, кого приглашаем.
- Таблица **17 3** - @username рабочих аккаунтов (их должно быть видно в Менеджере аккаунтов - сопоставление идёт по юзернейму).

**Настройки:**

| Настройка | Что делает | Что ставить |
|-----------|-----------|-------------|
| **Главный аккаунт (ID или @username)** | Кто раздаёт и снимает права | ID или @username вашего главного аккаунта |
| **Кол-во юзернеймов на аккаунт** | Сколько людей рабочий приглашает за заход | `20-30` |
| **Задержка после инвайта (сек)** | Пауза между приглашениями | `5-15` |
| **Кол-во одновременно работающих потоков** | Сколько рабочих работают параллельно | по числу рабочих, например `10` |
| **Кол-во циклов работающего потока/группы потоков** | Сколько заходов сделает каждый рабочий | `1` и больше |

<div class="box box-warning">
⚠️ Агрессивный режим, аккаунты расходуются быстро. Держите пул с запасом, разным волнам давайте разные аккаунты. Перед заливкой проверьте чат через "Проверить чат на ограничения".
</div>

<div class="box box-info">
ℹ️ Если рабочий вышел из чата в фазе 2, его права и так слетают - фаза 3 в этом случае просто страховочная зачистка.
</div>

## 17.5 Проверить чат на ограничения <span class="badge-new">Новое</span>

Режим-разведчик. Никого не приглашает и лимит аккаунта не тратит: аккаунт просто открывает каждую ссылку из `17 2` и проверяет, что за чат по ту сторону и не спрятал ли его Telegram.

**Что проверяется:**

1. **Теневой бан.** Ссылка открывается напрямую, но в глобальном поиске чата нет. Значит Telegram убрал его из выдачи - новые люди чат уже не найдут. Инвайт в такой чат работает, но своей аудитории он больше не набирает.
2. **Метки Telegram** - "скам" и "фейк". Такой чат почти не показывают людям, а аккаунты, которые в нём активничают, ловят ограничения быстрее.
3. **Официальное ограничение** - Telegram закрыл чат по жалобам, с указанием причины.
4. **Право приглашать** - можно ли вообще инвайтить в этот чат, или по ссылке канал/чужая закрытая группа.

Результат пишется в таблицу `17 2` в колонку **"Теневой бан"**, а право на инвайт - в колонку **"Задача"**. То есть после проверки можно сразу отсеять мусорные ссылки и запускать инвайт только по живым чатам.

**Настройки:**

| Настройка | Что делает | Что ставить |
|-----------|-----------|-------------|
| **Задержка после проверки чата (сек)** | Пауза между чатами | `3-6` |
| **Кол-во одновременно работающих потоков** | Сколько аккаунтов проверяют параллельно | `1-3` |

<div class="box box-info">
ℹ️ Ссылки делятся между аккаунтами: каждая проверяется один раз. Чем больше аккаунтов, тем быстрее пройдёт весь список.
</div>

<div class="box box-tip">
💡 Закрытые ссылки (<code>t.me/+...</code> и <code>joinchat</code>) проверяются <b>без вступления</b> в чат. Поиск к ним неприменим - закрытых чатов в поиске нет и без всякого бана, поэтому в колонке будет "Закрытая - поиск не проверяется".
</div>

## 17.7 Инвайт новых подписчиков из чата-донора <span class="badge-new">Новое</span>

Режим без списка людей. Аккаунт вступает в чужой чат (донор) и сидит в нём, а когда в донор заходит новый участник, через случайную задержку приглашает его в ваш чат. Приглашение идёт по ID: ключ доступа Telegram отдаёт вместе с событием вступления, резолв юзернейма не нужен - это самый бережный для аккаунта способ (см. 17.1.3).

**Как работает по шагам:**

1. Каждый аккаунт берёт свой чат-донор из `04 1` (один донор - один аккаунт, второй аккаунт в этот же чат не пойдёт) и целевой чат из `17 2`, при необходимости вступает в оба.
2. Аккаунт ждёт событий вступления в доноре. Новичок записывается в `17 1` с отметкой 🟡 и ставится в очередь.
3. Через задержку из настройки аккаунт приглашает новичка в целевой чат и пишет результат в `17 4`, строка в `17 1` получает 🟢 или 🔴.
4. Задача бессрочная: аккаунты сидят в донорах, пока вы не остановите задачу кнопкой остановки (в консольном режиме - введите `0` и нажмите ENTER).

**Что подготовить:**

| Таблица | Кто заполняет | Что вписывать |
|---------|---------------|---------------|
| `04 1 Парсер пользователей ссылки` | **Вы** | Ссылки на чаты-доноры. Ссылок не меньше, чем аккаунтов: аккаунт без донора завершится со статусом "нет свободного чата-донора" |
| `17 2 Инвайтер ссылки на группы` | **Вы** | Ссылка на ваш чат, куда приглашаем |
| `17 1 Инвайтер список пользователей` | Программа | Пойманные новички: ID, юзернейм, ID аккаунта, отметка |
| `17 4 Инвайтер результаты` | Программа | История приглашений |

**Настройки:**

| Настройка | Что делает | Что ставить |
|-----------|-----------|-------------|
| **Задержка перед инвайтом новичка (сек)** | Сколько ждать после того, как человек зашёл в донор. Мгновенный инвайт выглядит как бот, разброс обязателен | `120-600` |
| **Инвайтов в час на аккаунт (0 - без ограничения)** | Потолок скорости. Набрал норму - новички ждут в очереди, пока окно освободится | `4-6` |
| **Инвайтов в сутки на аккаунт (0 - без ограничения)** | Дневной потолок. Считается по таблице `17 4`, переживает перезапуск | `40` |
| **Пропускать новичков без юзернейма (1 - Да / 2 - Нет)** | `1` - звать только людей с юзернеймом, `2` - всех (инвайт по ID юзернейма не требует) | `2` |
| **Кол-во одновременно работающих потоков** | Сколько аккаунтов сидят в донорах одновременно | По числу аккаунтов |

<div class="box box-warn">
⚠ Режим работает только с группами и супергруппами: в каналах события вступления Telegram не отдаёт. Целевой чат тоже должен быть группой. Аккаунт должен реально состоять в доноре: в чате с заявками на вступление задача ждёт одобрения администратором.
</div>

<div class="box box-tip">
💡 В активном чате новичков будет больше, чем аккаунт может безопасно позвать. Лимиты в час и в сутки держат скорость сами, а очередь не теряется: не приглашённые за этот запуск остаются в <code>17 1</code> свободными строками, их можно позвать обычным Инвайтером (ключи доступа сохранены).
</div>

**Как читать лог:**

```
Поток 1: 12:03:11 123456: Инвайт новых подписчиков из чата-донора: сижу в https://t.me/donor (Донор), новичков приглашаю в https://t.me/my_chat
Поток 1: 12:07:40 123456: Инвайт новых подписчиков из чата-донора: новичок @ivan из https://t.me/donor, инвайт через 314 сек (в очереди: 1)
Поток 1: 12:12:54 123456: Инвайт новых подписчиков из чата-донора: @ivan: Приглашен: Обработан: [ 1 ] (успешно: 1, с ошибкой: 0)
Поток 1: 13:02:10 123456: Инвайт новых подписчиков из чата-донора: лимит в час выбран (5/5), в очереди 3, жду
```

## Общие настройки потоков (в режимах инвайта)

| Настройка | Что делает | Что ставить |
|-----------|-----------|-------------|
| **Кол-во одновременно работающих потоков** | Сколько аккаунтов работают параллельно | `1-3` |
| **Задержка перед выполнением следующего потока/группы потоков (сек)** | Пауза перед запуском следующего аккаунта | `15-40` |

Про потоки и задержки подробно - [глава 3](../Руководство/03_Общие_параметры_и_форматы.md).

## Живой пример

**Задача:** наполнить свою группу `t.me/mygroup` целевой аудиторией из 300 юзернеймов, собранных парсером.

**Подготовка:**
1. В `17 1` вставлены 300 юзернеймов.
2. В `17 2` - одна ссылка на вашу группу.
3. Выбран режим **17.4 Инвайтер админами** - чтобы добавить больше людей с меньшего числа аккаунтов.

**Настройки:**

| Настройка | Значение |
|-----------|----------|
| Кол-во юзернеймов на аккаунт | `40-50` |
| Задержка после инвайта (сек) | `30-60` |
| Брать пользователей | `2` (из списка) |
| Потоки | `2` |

**Результат:** аккаунты по очереди заходят в группу и приглашают людей, кратковременно повышая их до админов ради обхода лимита. За несколько проходов группа наполняется живыми участниками из вашего списка.

---

## Статусы в таблице `17 2`

| Статус | Что значит |
|--------|-----------|
| `Инвайт разрешен` | В группу можно приглашать - идёт работа |
| `Инвайт запрещен` | В этой группе инвайт закрыт настройками админа |
| `Не инвайчу в канал` | По ссылке канал, а не группа |
| `Нерабочая ссылка` | Ссылка мёртвая или неверная |
| `Нет доступа к группе` | Чат закрыт для этого аккаунта |
| `Нет прав администратора` | Приглашать в этот чат разрешено только администраторам. В режиме 17.4 - у аккаунта нет права "Добавление администраторов": софт проверяет это перед стартом и юзернеймы не тратит |
| `Не хватает прав администратора` | Аккаунт админ, но нужной галочки у него нет. Для инвайта нужно "Добавление участников", для назначения админов - "Добавление администраторов" |
| `Нет прав писать в группе` | Аккаунту закрыта отправка сообщений в чате |
| `Заявка на вступление не принята` | В чате включено подтверждение вступления. Аккаунт подал заявку, но участником ещё не стал, а не участник никого добавить не может. Примите заявку - на следующем круге аккаунт продолжит сам |
| `Telegram отклоняет инвайт в этот чат` | Группа разрешает участникам добавлять людей, на аккаунте ограничений не видно, а Telegram всё равно отклонил приглашение. Обычно временно. Аккаунт остаётся свободным, на следующем круге группа берётся снова |

Если группа разрешает участникам добавлять людей, а Telegram всё равно отказал аккаунту, софт сначала выясняет, кто виноват. Telegram отвечает одной и той же ошибкой и на ограничение аккаунта, и когда временно не даёт приглашать в конкретный чат, поэтому по одному отказу аккаунт не блокируется.

Аккаунт получает статус `🟧 Нет права приглашать (ограничение Telegram)` в таблице `01 1 Менеджер аккаунтов` и снимается с задачи до ручного сброса статуса только в двух случаях:
- за этот запуск он получил такой отказ уже во второй разной группе;
- @SpamBot прямо сообщает, что на аккаунте есть ограничение.

Обычно так ведут себя новые или перегретые аккаунты - им нужен прогрев. Во всех остальных случаях виноватым считается чат: группа получает статус `Telegram отклоняет инвайт в этот чат`, аккаунт остаётся свободным и на следующем круге пробует снова. В логе при этом видно, что ответил @SpamBot, сколько аккаунтов подряд получили отказ на этой группе и какую ошибку вернул Telegram.

Если администратор группы снял право добавлять участников именно с этого аккаунта, в логе пишется `Аккаунту закрыт инвайт в этой группе`: аккаунт не блокируется, статус группы для остальных не меняется.

То же в режиме **17.4 Инвайтер админами**: если аккаунт администратор с правом "Добавление администраторов", а Telegram всё равно отказывает при назначении, это ограничение аккаунта, а не чата. Аккаунт получает тот же статус `🟧`, ссылка остаётся рабочей. Если человек из списка уже администратор чата, назначенный кем-то другим, в результатах он помечается `Уже администратор`, а аккаунт идёт дальше по списку.

## Колонка "Теневой бан" в таблице `17 2`

Заполняется режимом **17.5 Проверить чат на ограничения**.

| Значение | Что значит |
|----------|-----------|
| 🟢 `Ограничений нет` | Чат чистый: в поиске виден, меток нет |
| 🔴 `Скрыт из поиска` | Теневой бан - по ссылке чат открывается, а в поиске его нет |
| 🔴 `Помечен как скам` | Telegram пометил чат как мошеннический |
| 🔴 `Помечен как фейк` | Telegram пометил чат как поддельный |
| 🔴 `Ограничен Telegram (...)` | Официальное ограничение с причиной |
| 🔴 `Нет доступа к чату` | Аккаунт забанен в чате или чат закрыт |
| 🟡 `Закрытая - поиск не проверяется` | Приватный чат по ссылке-приглашению, поиск к нему неприменим |
| 🟡 `Ошибка проверки` | Проверить не удалось, запустите режим ещё раз |
| 🔴 `Нерабочая ссылка` | Ссылка мёртвая или неверная |

## Отметки в таблице `17 1` (при работе по списку)

| Отметка | Что значит |
|---------|-----------|
| 🟢 | Пользователь успешно приглашён |
| 🔴 | Пригласить не удалось (приватность, бан, несуществующий юзернейм и т.п.) |
| 🔴 `Нет хеша у аккаунта` | Строка с ID досталась аккаунту без ключа доступа (см. 17.1.3) |

## Частые ошибки

| Симптом | Решение |
|---------|---------|
| Задача сразу завершается | В `17 1` (или `17 3`) все строки уже обработаны или список пуст. Очистите отметки или добавьте юзернеймы |
| Везде "Инвайт запрещен" | В этих группах приглашения закрыты - вы должны быть админом/владельцем, либо выбирайте другие группы |
| Много 🔴 "Запрет на инвайт" | У людей закрыта приватность на добавление в группы - это норма, часть аудитории всегда недоступна |
| Аккаунт быстро перестаёт приглашать | Поймал спамблок на инвайты (сутки). Уменьшите "Кол-во юзернеймов на аккаунт" и увеличьте задержку |
| В чате с подтверждением вступления инвайт не идёт | Это нормальный ход: аккаунт подал заявку и ждёт. В таблице `17 2` будет "Заявка на вступление не принята", у аккаунта - "Ожидает подтверждения заявки". Примите заявку, чистить статус вручную не нужно - следующий круг подхватит аккаунт сам |
| Люди в группу заходят, а сама она не растёт | Прогоните режим **17.5** - возможно чат в теневом бане и его не видно в поиске |
