# История версий AlexSoftClub

Полный список изменений по версиям, новые сверху. Обновление в программе приходит автоматически.

## v2.37

**Клонер каналов**
- Новая настройка "Старые посты при мониторинге (1 - копировать / 2 - только новые)": при 2 старые посты источника не переносятся, в ваш канал попадают только записи, вышедшие после запуска мониторинга
- Фикс: перевод постов не работал, если API-ключ в "24 Настройки LLM API" был вставлен с переносом строки или пробелами - теперь лишние символы убираются автоматически

## v2.36

**Прогреватор аккаунтов**
- Новая задача 28 "Прогреватор аккаунтов" (раздел АКТИВНОСТЬ): аккаунты несколько дней ведут себя как обычные люди - ищут каналы по случайным словам и подписываются, читают посты, ставят реакции, пишут комментарии, смотрят сторис и переписываются друг с другом
- Нагрузка растёт постепенно: в первый день действий мало, к последнему дню прогрева - больше. Сколько действий в первый и последний день, задаётся в настройках
- Работает только в активные часы (по умолчанию с 9 до 23), действия дня разбиты на несколько сессий с паузами
- Комментарии и переписку между аккаунтами можно поручить нейросети (настройки "Комментарии через ИИ" и "Сообщения через ИИ"): в переписке ИИ видит последние сообщения диалога и продолжает разговор
- Аккаунты не комментируют одно и то же: под одним постом пишет только один ваш аккаунт, в один канал - не чаще раза в день, а другие аккаунты в этот канал 3 дня не пишут
- Один раз за прогрев оформляет профиль: пустое био и аватарку берёт из папки Data/Прогрев
- Прогресс каждого аккаунта виден в таблице 26 1, все действия - в журнале 26 5. Прогретые аккаунты задача больше не берёт

## v2.35

**Менеджер аккаунтов**
- Новый пункт 12 "Открыть в Telegram Desktop": аккаунты открываются в Telegram Desktop, каждый в своём окне. Для Desktop создаётся отдельная сессия, поэтому софт и Desktop не мешают друг другу (больше не будет ошибки авторизации, как при открытии той же tdata)
- Desktop с первой секунды работает через прокси аккаунта - ваш IP не светится
- Telegram.exe нужно положить в папку программы, сессии Desktop хранятся в папке "Telegram Desktop"
- В настройках пункта задаётся, сколько аккаунтов открыть за раз

## v2.34

**Клонер каналов**
- Режим мониторинга: если Telegram отключил сессию аккаунта (ключ используется где-то ещё), мониторинг сразу останавливается, а аккаунту ставится понятный статус - раньше софт часами повторял запросы и писал одну и ту же ошибку в лог

**Инвайтер**
- Инвайт новых подписчиков из чата-донора: то же самое - при отключённой сессии задача останавливается, а не переподключается бесконечно

## v2.33

**Масстегинг сторис**
- Софт сам определяет, есть ли у аккаунта Premium, и показывает его лимиты: длина подписи (без Premium - 200 символов), сколько сторис можно опубликовать сейчас, за неделю и за месяц
- Если подпись длиннее лимита аккаунта, сторис не публикуется и выводится ошибка с длиной подписи и подсказкой: сократить описание (14 3) или число отметок в настройках
- Если Telegram уже не даёт публиковать сторис (исчерпан лимит), аккаунт останавливается сразу, без загрузки файлов
- Вместо общего "Ошибка публикации сторис" теперь понятные статусы: лимит активных сторис, недельный/месячный лимит (с временем ожидания), нужен Premium, Telegram не принял файл
- При ошибке публикации пользователи для отметки возвращаются в очередь и достанутся другим аккаунтам
- Режим клонирования эталонов: длинное описание больше не обрезается молча - выводится ошибка про длину подписи

## v2.30

**Новая задача 26 "Чат-имитация" (раздел "Имитация")**
- Оживление своих чатов силами ботов, без расхода аккаунтов. Каждый бот (токен от @BotFather) закреплён за одним своим чатом, где он уже добавлен админом. Пары "чат - бот" задаются в таблице "24 1", фразы для каждого чата - в "24 2"
- Все боты работают одновременно и независимо: случайная пауза (настройка "Задержка между фразами (сек)", по умолчанию 60-180), случайная фраза из набора этого чата, отправка. Фразы не повторяются, пока не пройдёт весь набор, и одна и та же фраза не идёт два раза подряд
- Задача работает бессрочно, останавливается вводом 0 и ENTER. Отправленные фразы пишутся в "24 3"

## v2.29

**Рассыльщик/Дозвонщик в ЛС (задача 15) - новая подзадача "Праймер в ЛС"**
- Аккаунт включает в личке таймер автоудаления, не отправляя ни одного сообщения. Человеку приходит уведомление "Имя включил(а) автоудаление сообщений", и он заходит в профиль посмотреть, кто это
- Люди берутся из того же списка "15 1", результаты пишутся в "15 3". Настройки: кол-во юзернеймов на аккаунт, задержка после оповещения, срок автоудаления (1 день / 1 неделя / 1 месяц)
- Таймер обратно не выключается, чтобы в чате была только одна строка
- Если Telegram ограничил аккаунт на действия с незнакомцами (спам-блок), аккаунт сразу останавливается и уходит в ограничение на сутки, а не идёт дальше по списку. Недоработанный юзернейм возвращается в очередь

## v2.22

**Инвайт новых подписчиков из чата-донора (задача 17, новый пункт подменю)**
- Аккаунт вступает в чужой чат-донор из "04 1" и ждёт новых участников. Когда кто-то вступает, аккаунт через случайную задержку приглашает его в ваш чат из "17 2". Список людей заранее не нужен
- Приглашение идёт по ID без резолва юзернейма: ключ доступа приходит вместе с событием вступления. Ключ сохраняется в "04 3", новичок записывается в "17 1" с ID, юзернеймом и ID аккаунта
- Один донор - один аккаунт: два аккаунта в одном чате одного новичка дважды не позовут. Ссылок в "04 1" должно быть не меньше, чем аккаунтов
- Настройки: задержка перед инвайтом новичка (по умолчанию 120-600 сек), лимит в час (5) и в сутки (40) на аккаунт по таблице "17 4", пропуск новичков без юзернейма
- Задача бессрочная: останавливается кнопкой остановки, в консоли - 0 и ENTER. Не приглашённые из очереди остаются в "17 1" свободными строками
- Работает только с группами и супергруппами, в каналах Telegram события вступления не отдаёт

## v2.21

**Инвайт по ID - люди без юзернейма (задачи 4 и 17)**
- Парсер пользователей: новая настройка "Сохранять пользователей без юзернейма (1 - Да / 2 - Нет)". При 1 в таблицу "04 2" попадают и те, у кого юзернейма нет - с ID, именем и ссылкой на чат. По умолчанию 2, у остальных клиентов ничего не меняется
- В таблице "17 1 Инвайтер список пользователей" появилась колонка "ID пользователя" (первая): вписывайте юзернейм, ID или оба. Строки с одним ID приглашаются по ID. Порядок колонок теперь у всех одинаковый: ID пользователя, Юзернейм, ID аккаунта, Задача; колонка "Ссылка на чат-источник" убрана - чат берётся из "04 1"
- Инвайт по ID требует, чтобы каждый аккаунт сам "увидел" человека в чате: Telegram выдаёт каждому аккаунту свой ключ доступа. Для этого в парсере новая настройка "Парсить только людей из списка Инвайтера (1 - Да / 2 - Нет)": при 1 каждый выбранный аккаунт проходит все ссылки из "04 1" и ищет в них людей, чьи ID вписаны в "17 1". Ключи сохраняются в служебную таблицу "04 3", повторный запуск ищет только тех, кого аккаунт ещё не видел
- Порядок работы: 1) первый аккаунт парсит чат с "Сохранять без юзернейма = 1"; 2) вы переносите нужных людей в "17 1" (ID и юзернейм) и удаляете лишних; 3) запускаете парсер с "Парсить только людей из списка Инвайтера = 1" на аккаунтах для инвайта; 4) запускаете Инвайтер - строки с ID уходят без резолва и без задержек
- Работает в обычном инвайте, быстром режиме пачками, "Инвайтер админами" и "Авто-инвайт админами"
- Без подготовки Инвайтер работает как раньше: юзернеймы берутся и приглашаются как обычно, строки с одним ID аккаунт без ключа не трогает, в консоли пишется, сколько таких строк и что запустить
- Фикс: при открытии экрана настроек софт удалял из "04 2" строки без юзернейма - больше не удаляет

**Инвайтер (задача 17)**

Telegram отвечает одной и той же ошибкой и на ограничение аккаунта, и когда временно не даёт приглашать в конкретный чат - софт всегда винил аккаунт. В логе клиента так подряд легли 18 рабочих аккаунтов на одной группе, куда за пару минут до этого те же аккаунты успешно инвайтили

Иначе виноватым считается чат: в таблице "17 2" группа получает пометку "Telegram отклоняет инвайт в этот чат", аккаунт остаётся свободным для следующего круга

- В лог при остановке по группе добавлен исходный ответ Telegram (например ChatAdminRequiredError) - по логу теперь видно, что именно ответил сервер
- Касается обычного инвайта, быстрого режима пачками и инвайта админами

## v2.18

**Тегер (задача 20)**
- Новый режим упоминаний "3 - постит бот": сообщение в чат отправляет ваш бот, поэтому под постом остаются кнопки. Обычный аккаунт кнопки ставить не умеет, это умеет только бот
- Работает как привычный режим 1: аккаунт отбирает активных участников чата и прячет в пост невидимые упоминания, каждый упомянутый получает уведомление
- Текст, картинка и кнопки берутся из вашего готового поста: сделайте пост с кнопками в своём канале и вставьте ссылку на него в таблицу "20 2 Тегер сообщения"
- Что нужно подготовить: создать бота у @BotFather, вставить его токен в настройку "Токен бота (режим 3)" и добавить бота в чат с правом отправлять сообщения
- Переносятся кнопки-ссылки. Кнопки с обработкой нажатия не переносятся: нажатие уходило бы чужому боту и кнопка молчала бы
- В один пост уходит не больше 50 упоминаний, при большем количестве Telegram начинает их срезать
